# แนวทางทำงานโค้ดแบบ Junior Developer

ใช้กับงานเขียนหรือแก้โค้ดในโปรเจกต์ โดยยึดคำสั่งเฉพาะของผู้ใช้และข้อกำหนดของโปรเจกต์เป็นหลัก

## ก่อนเริ่ม

- อ่านคำสั่งของโปรเจกต์ โครงสร้างไฟล์ สถานะ Git และไฟล์ checkpoint ที่มีอยู่ก่อนแก้ไข
- กำหนดส่วนงานเล็ก ๆ ที่ตรวจสอบและ commit แยกได้ตามเหตุผล โดยไม่สร้างไฟล์หรือชั้นโค้ดเกินความจำเป็น

## เขียนโค้ด

- ใช้ชื่อไฟล์และโฟลเดอร์เป็นภาษาอังกฤษ และตั้งชื่อฟังก์ชันกับตัวแปรให้สื่อความหมาย
- แยกไฟล์ตามหน้าที่เมื่อช่วยให้เข้าใจง่าย ใช้โค้ดตรงไปตรงมาและรูปแบบที่สอดคล้องกับโปรเจกต์
- เขียนคอมเมนต์เป็นภาษาไทยเพื่ออธิบายเจตนา ขั้นตอนที่ไม่ชัด หรือข้อควรระวัง ไม่ต้องคอมเมนต์ซ้ำสิ่งที่โค้ดบอกอยู่แล้ว
- หลีกเลี่ยงการปรับโครงสร้างส่วนที่ไม่เกี่ยวกับงาน

## ตรวจสอบและบันทึกความคืบหน้า

- รันการตรวจที่เหมาะกับการเปลี่ยนแปลง เช่น test, build, lint หรือทดลองขั้นตอนใช้งานจริง ตรวจผลลัพธ์และแก้ปัญหาที่พบ
- สร้างหรืออัปเดต `AI_CHECKPOINT.md` ที่รากโปรเจกต์เป็นภาษาไทย หากโปรเจกต์มีไฟล์ checkpoint อยู่แล้ว ให้ใช้ไฟล์เดิมแทน
- บันทึกงานที่ทำเสร็จและตรวจผ่านแล้ว ผลและคำสั่งที่ใช้ตรวจ สิ่งที่ยังค้างหรือมีข้อจำกัด และขั้นตอนถัดไป เพื่อให้ AI ตัวถัดไปทำงานต่อได้
- ระบุให้ชัดเมื่อตรวจบางอย่างไม่ได้ และอย่าทำเครื่องหมายว่างานนั้นผ่านการตรวจหรือเสร็จสมบูรณ์

## Commit

- แบ่ง commit ตามส่วนงานที่มีความหมาย หลังตรวจส่วนงานนั้นแล้ว ใช้ชนิด Conventional Commits ที่ตรงกับการเปลี่ยนแปลง และเขียนคำอธิบายหลัง `:` เป็นภาษาไทย เช่น `feat: เพิ่มหน้าค้นหา`, `fix: แก้การคำนวณยอดรวม`, `refactor: แยกฟังก์ชันตรวจข้อมูล`
- รวมการอัปเดต checkpoint ใน commit ที่เกี่ยวข้อง หลีกเลี่ยงการนำการแก้ไขเดิมของผู้อื่นหรือไฟล์ที่ไม่เกี่ยวข้องเข้า commit
- หากยังไม่มี Git repository ให้เริ่ม Git ได้เมื่อชัดเจนว่าเป็นโปรเจกต์ใหม่ที่รับผิดชอบทั้งโปรเจกต์ มิฉะนั้นให้แจ้งเหตุผลที่ commit ไม่ได้

## ส่งมอบ

สรุปสิ่งที่เปลี่ยน วิธีตรวจและผลจริง รายการ commit และงานค้างหรือข้อจำกัดอย่างกระชับ
